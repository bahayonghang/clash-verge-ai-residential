# 优化实时连接界面

## Goal

让 Windows 11 操作员在「实时连接」页能快速收敛到需要处理的连接：筛选条件容易发现、编辑和清除；表格在拖动列宽与实时刷新时保持稳定可预测；表格上方能以当前查询口径展示两个最有用的实时占用摘要。优化保持专家工具密度与现有数据诚实边界，不把观测下界写成账单或把未知填成零。

## Background / Confirmed facts

- 用户提供的截图是当前界面的视觉/问题参考，不是需要照抄的产品指令；本任务的产品约束以 `PRODUCT.md`、`DESIGN.md` 与 `.trellis/spec/residential-monitor/frontend/` 为准。
- 当前实时页在 `residential-monitor/src/main.ts:253-399` 一次性拼出状态、筛选、列显隐、列宽、排序与表格。筛选是「只看家宽」复选框 + 最多 8 条字段条件；列操作和筛选控件共用一条工具条。
- 筛选字段与比较/单位由 `src/main.ts:311-344`、`src/format/live-filter-units.ts` 生成；`src/main.ts:1270-1347` 在 change 时刷新，且对条件值同时保留 input/change 两条路径，容易造成编辑期间的频繁重绘与焦点干扰。
- 表格使用 `<colgroup>` 像素宽度和 `table-layout: fixed`（`src/main.ts:374-396`、`src/styles.css:524-588`），布局模型把列宽 clamp 到 72–640px 等范围并把可见列宽求和为总表宽（`src/live-table-layout.ts:18-159`）。拖动时 `src/main.ts:1437-1463` 直接修改列与整表宽度，松手后再持久化并整页重绘；这需要明确「列宽变化」与「容器/整表宽度变化」的边界。
- `query_live_connections` 是实时表的权威查询，默认 `limit=200`，筛选和排序在后端执行（`src/ipc/live-session.ts:14-34,90-105`；`src-tauri/src/c2/query.rs:7-28,74-163`）。连接 DTO 已提供下载、上传、速率、时长、主机、链路、规则、进程、来源、目标和类型等事实（`src/dto.ts:41-64`）。
- 前端规范明确：实时筛选与排序只留当前会话；列宽/显隐写入 `live_table_layout`；前端不得自行实现分类、守恒、Top N 或导出统计；缺口、未知、暂停和无行必须继续分开表达（`.trellis/spec/residential-monitor/frontend/view-state.md:3-19`；`dto-and-decoding.md:20-51`）。
- 既有归档任务 `08-19-live-table-sort-width` 已交付列排序、数值筛选、像素列宽、显隐与持久化；本任务是针对真实使用反馈的二次 UX/交互优化，不重新发明已有排序/筛选数据契约，也不扩展为详情抽屉、虚拟化或关闭全部连接。

## Requirements

### R1. 可扫读、可恢复的筛选工作区

- 把筛选从混合工具条重组为清晰的「快速筛选 + 已应用条件 + 添加条件」层级：`只看家宽` 为明确的主开关；已有条件以可读的条件 chip/行展示；增加、删除、清空和条件数量上限均有可见状态。
- 保留当前支持的字段、文本 `contains/exact`、数值比较与单位换算、最多 8 条 AND 以及空值忽略语义；字段切换仍重置比较模式/单位/值。
- 编辑文本条件时不得因每次按键触发整页重绘而丢失焦点或光标；采用明确的应用时机（推荐：回车/失焦应用，提供清空/取消）或等价的防抖策略，并在任务设计中写清请求竞态与过期响应处理。
- 为已应用筛选显示结果数量/状态以及无匹配的下一步；筛选失败、订阅缺口、暂停和未配置仍使用现有专门空态，不用“无数据”混淆。
- 列显隐入口与筛选入口在信息层级上分离；窄窗口下控件可换行或折叠，不出现横向溢出。

### R2. 稳定的固定列宽与拖动逻辑

- 保持像素列宽和 `table-layout: fixed` 的专家表格模型：实时数据刷新、排序、筛选和整页重绘不得按内容重新分配列宽，不得出现列头/单元格抖动。
- 拖动只改变目标数据列的宽度；总表宽度随可见列宽总和更新，以便横向滚动，但不得让容器宽度或未拖动列隐式缩放。隐藏/恢复列、恢复默认和切换主题/语言后宽度仍可预测。
- 拖动开始、移动、结束与取消（pointer capture/窗口失焦）要有明确状态；松手只提交一次本机布局持久化，失败保持内存布局并给出可诊断但不打断操作的反馈。
- 为列调整把手提供可见 focus/键盘替代或等价可达操作说明；继续使用原生表格、排序 `aria-sort` 和单行省略，不能用不可访问的纯视觉拖拽替代表格语义。
- 既有列宽 clamp、至少保留一列可见、非法布局回退默认模板的安全约束必须保留并覆盖回归测试。

### R3. 表格上方的两个实时占用摘要

- 在表格前增加两个紧凑、可扫读的统计卡/图标区域，显示当前查询口径下最值得关注的连接占用，并同步展示标签、数值单位、更新时间/样本状态和未知/缺口语义。
- 摘要必须与当前筛选、`只看家宽`、排序查询和实时刷新保持一致；筛选无结果、连接暂停、订阅缺口或能力不足时不伪造 0 或沿用旧值而不标明状态。
- 统计不得在前端从表格页自行重算 Top N、全量或守恒；需要扩展时由 Rust 查询/DTO 提供明确、可校验的摘要契约，或在证据证明现有 DTO 足够且不产生截断偏差时采用可审计的最小实现。
- 每个摘要（若含图形）必须有同口径的文本/数据说明，满足现有「图表必须有对应数据表」与无障碍约束；不引入远程图标、CDN 或 UI 框架。

### R4. 兼容性、数据诚实与交互状态

- 不新增顶级路由，不改变关闭单条连接、Monitor Channel/resync、C2 collector 生命周期、控制器 secret 或存储边界。
- 中英文文案完整；保持 `未知`、暂停、未连接、未配置、已连接无行、订阅缺口等专门状态。
- 所有新增/修改控件具备默认、hover、focus、disabled、loading、error、success 状态；保留键盘导航、`prefers-contrast: more`、`prefers-reduced-motion` 与 1200×800 默认窗口的专家密度。

## Out of scope

- 不实现详情抽屉、全屏连接详情、虚拟化 10k 行、分页 UI、列重排、Excel 式多列菜单或关闭全部连接。
- 不改变 C1/C2 核算、分类、coverage、Top N/报告统计、历史报告或数据库 schema，除非为 R3 摘要契约补充最小、独立且经验证的后端 DTO/query 能力。
- 不替换产品整体视觉世界，不复制截图来源产品的品牌、文案或功能；不引入新的运行时依赖、远程资源或 UI 框架。

## Acceptance Criteria

- [ ] AC1：在中文/英文和四套主题下，快速筛选、已应用条件、添加/删除/清空、只看家宽和列显隐的层级清晰；键盘可完成主要操作，1200×800 与窄窗口无重叠/溢出。
- [ ] AC2：文本条件编辑不会因每次按键整页重绘丢失焦点/光标；应用、取消、清空和过期请求行为有自动化测试；后端收到的条件仍是现有字段/模式/单位语义。
- [ ] AC3：实时刷新、排序、筛选和重绘过程中每个可见列保持持久像素宽度；拖动只改变目标列，总表横向滚动稳定；取消/失败路径不遗留 dragging 状态；布局解析、clamp、隐藏最后一列和持久化回归测试通过。
- [ ] AC4：两个摘要在当前查询口径下显示经审计的实时占用事实和更新时间/状态；无匹配、暂停、缺口、未知不会伪造 0；摘要与表格数据契约一致，不在前端偷偷重算全量或 Top N。
- [ ] AC5：所有摘要/图形（如有）提供对应文本或数据表；`aria-sort`、可见 focus、对比度、reduced-motion、无障碍状态和中英文文案通过代码检查与目标界面实拍/手动检查。
- [ ] AC6：相关前端 typecheck/lint/unit tests、Rust 目标测试（如 R3 扩展 query/DTO）和 `git diff --check` 通过；不影响既有 monitor channel、空态、关闭单条连接和 secret 扫描。

## Key decision

- 已确认两个摘要采用“当前筛选结果中下载累计最高的连接”与“当前筛选结果中上传累计最高的连接”。卡片显示连接可识别标签（主机优先、必要时进程/目标）、方向值、样本时间和数据状态；不得把截断的 `limit=200` UI rows 当成全量 Top 1，必要时由后端以同一 filter query 返回可校验 summary。

## Task map

这是一个复杂 UI/数据契约任务，规划阶段拆为可独立验收的子任务：筛选工作区交互、固定列宽/持久化交互、实时摘要 DTO/卡片与最终集成检查；子任务顺序、依赖和回滚点写入 `design.md` 与 `implement.md`。本任务保持 planning，尚未授权 `task.py start` 或产品代码修改。
