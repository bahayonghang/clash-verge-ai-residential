# 家宽地址流量拆解与趋势明细优化

## Goal

让用户在「家宽」页直接回答两个问题：近一段时间内，哪些实际目的主机/地址消耗了最多上行和下行流量；最新一个趋势时间桶的统计量是多少。`target` 只负责界定哪些连接属于家宽流量，不再作为唯一的拆解维度。

## Background

- 2026-08-25 用户截图中，「按 TARGET 节点排名」只有一个“未知”条目（上行 10.8 GiB、下行 11.1 GiB、份额 100%），无法定位上行/下行热点地址。
- 同一页的实时快照已经能显示具体目的主机（如 `agentn.api5.cursor.sh`、`cli-chat-proxy.grok.com`），说明产品具备可展示的主机身份，只是聚合区仍按 `target` 分组。
- 趋势图下方明细从较早时间向较晚时间排列；用户要求最新时间桶置顶，并优化当前缺少清晰表头、层级与行态反馈的表格样式。

代码分析确认，家宽聚合区当前使用 `grouping: "category"` 且没有家宽过滤；C3 虽声明并回显 `ReportQuery.sort`，排名 SQL 却全部固定按下行降序后截断。完整证据见 `research/findings.md`。

## Requirements

- R1：家宽聚合排名必须在“属于家宽”的筛选口径内，按实际目的主机/地址拆解，而不是按配置 `target` 聚合成一个桶。
- R2：地址口径应复用产品已有主机身份语义；域名可得时显示域名，域名不可得时回退到目的 IP，不虚构隧道内域名。
- R3：用户必须能分别识别上行流量最大和下行流量最大的地址；方向切换触发权威查询，排序发生在 Top N 截断之前，数值和份额跟随当前方向，不能只重排下载候选集。
- R4：趋势图保持时间从旧到新的绘制语义；图下明细按时间从新到旧展示，最上方为当前查询窗口内最新时间桶。
- R5：趋势明细应采用可扫读的表格结构，明确时间、上行、下行列，并提供与当前设计系统一致的 sticky 表头、对齐、分隔、悬停和滚动表现。
- R6：中文和英文文案、宽屏与窄屏布局、空数据/加载/错误状态保持一致可用。
- R7：不得把 `target` 节点改名为目的地址；必须在查询契约中显式区分“家宽筛选依据”和“排名分组维度”。
- R8：家宽手动报告 / 导出使用与页面一致的“家宽子集 + Host 分组”口径；未命中精确 target 时显示诚实空态，不回退到全量未知流量。

## Acceptance Criteria

- [x] AC1：给定同一窗口内至少两个家宽目的主机/地址，家宽排名展示多个独立条目，且每条上行、下行及合计与后端查询结果一致。
- [x] AC2：上行热点与下行热点可分别识别；`topN=1` 且二者不是同一地址时，上行 / 下行查询分别返回正确首行，证明排序发生在截断前。
- [x] AC3：有 Host/嗅探 Host 的连接按域名聚合；无域名的连接按目的 IP 聚合；缺失值语义与现有归因契约一致。
- [x] AC4：趋势明细首行是返回序列中 `bucketUtc` 最大的条目，后续严格递减；趋势图数据顺序不被反转。
- [x] AC5：趋势明细包含可访问的时间 / 上行 / 下行表头，数值右对齐且使用等宽数字，滚动区域具有 sticky 表头、边框、稳定间距和清晰行分隔；窄屏可横向滚动。
- [x] AC6：覆盖中文/英文、空数据、单桶、多桶、同值排序、未知地址和窄屏布局的前端回归测试。
- [x] AC7：后端测试证明家宽过滤发生在分组之前，非家宽连接不会进入地址排名；本任务不新增 DTO 字段，现有 `queryEcho` / `ReportResult` 严格解码保持通过。
- [x] AC8：家宽手动报告的 `queryEcho` 为 Host 分组且带 residential category filter；导出保留每个地址的上下行值，不再输出单一 target 桶。
- [ ] AC9：相关聚焦测试、Rust 测试、前端测试、类型检查、`just ci`、Trellis 校验与 `git diff --check` 通过；原生 WebView 的宽 / 窄屏及深浅色视觉检查单独记录证据，未执行时标为 `UNVERIFIED`。

## Out of Scope

- 不解析 SOCKS5/TLS 隧道内部域名，不把进程名当成目的地址。
- 不修改 Clash 扩展脚本的路由域名、用户私有配置、凭据或现有数据库内容。
- 不在本任务内重新定义 `target` 配置的精确匹配语义；仅修正家宽页的拆解维度与展示。
- 不新增趋势图 / 表联动、点击钉住或通用表格设计系统；不重构全局报告页与其它维度页。
