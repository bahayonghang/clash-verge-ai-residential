# 修复家宽历史地址累积统计读取

## Goal

让「家宽」页在用户选择的滚动时间窗口内，持续展示哪些目的主机 / 地址累计消耗了最多家宽上行和下行流量，并能查看随时间变化的累积序列；应用长时间运行、窗口隐藏后再打开或已有历史尚未写入分类键时，均不得退化为与实际数据不符的空榜单。

## Background and Confirmed Facts

- 用户截图显示实时区域已有 36 条命中连接和可识别的目的地址，但「家宽目的地址排名」与「流量趋势」均为空；家宽占比为 0%，同时可归因观测有非零流量。这不是单纯的图表绘制问题。
- 家宽聚合前端已按 `grouping="host" + filters.category="__residential__"` 请求历史报告，并用当前方向 / Top N 的 `queryEcho` 拒绝陈旧排名；见 `residential-monitor/src/components/features/residential/aggregate-section.tsx:39-56`、`aggregate-model.ts:13-28`。
- 历史核算只接受链路节点与已配置 target 完全相等；实时筛选还接受节点名包含「家宽」。两套已发布口径被明确分开；见 `residential-monitor/src-tauri/src/residential.rs:1-34`。
- `primary_category_id` 是 `__residential__` 历史过滤的唯一判据；为空时 totals、series 和 rankings 全部被过滤；见 `residential-monitor/src-tauri/src/c3/sql.rs:12-13,22-60,128-138,378-385`。
- 安装实例数据库的脱敏聚合检查（2026-08-31 11:15 本地时间）确认：264,654 个历史会话均有 Host，`primary_category_id` 非空数为 0，category 字典数为 0；配置 target 为「家宽」且完全相等命中为 0，但链路节点包含该 target 的命中为 70,282 个会话。最近 24 小时 raw 数据中，包含匹配可恢复 25,022 个会话和非零上下行量。未读取或记录具体 Host、IP、进程路径或凭据。
- 相对时间范围在 `App` 首次挂载或用户切换预设时计算一次；开启自动刷新不会推进 `rangeEndUtc`。长驻应用中的「近 24 小时」因此实际是启动时冻结的旧窗口；见 `residential-monitor/src/app.tsx:31-33,95-104` 与 `lib/time-range.ts:15-38`。
- 安装实例进程在 2026-08-29 20:09 启动，截图于 2026-08-31 11:08 仍显示「近 24 小时」；数据库 coverage 最后一条结束时间与启动时间接近。这与冻结窗口代码路径一致，但最终修复必须由回归测试证明，不能只依赖本机时间推断。
- 既有 `connection_chain` 为 265,054 个会话保留了链路节点，因此在 raw 保留期内存在恢复历史家宽归属的权威输入，无需从前端或 Host 名猜测。

## Requirements

- R1：`5m / 30m / 1h / 24h / 7d / 30d / today` 相对预设在自动刷新开启时必须滚动到当前时间；从暂停恢复自动刷新或重新选择预设时必须立即重算窗口。关闭自动刷新时保留一个明确的冻结快照，不得让标签仍暗示窗口正在推进。
- R2：家宽实时筛选、历史核算、份额、地址排名、趋势和手动报告必须共享一个可解释的家宽归属规则；归属只能来自配置 target 与持久化链路节点，不能从 Host、进程或流量大小推断。
- R3：既有 raw 保留期内已经保存 `connection_chain`、但 `primary_category_id` 为空的记录，升级后必须立即可用于当前时间窗口的家宽累计统计；用户不能被要求等待新连接或手工改库。
- R4：未来采样必须在同一共享归属规则下写入稳定分类，使份额、Top N、趋势与后续 hourly / daily 物化保持一致；不得只在前端重排或聚合。
- R5：家宽页必须明确显示统计窗口的实际起止 / 截止时间与最近更新状态，使用户能区分滚动窗口、暂停快照和陈旧结果。
- R6：空态必须区分：窗口内确实没有家宽命中、没有采集覆盖、能力不支持、查询失败和正在刷新；可恢复的历史链路不得显示成「没有排名」。
- R7：地址排名继续由后端在 Top N 截断前按当前方向排序；趋势图保持旧到新，趋势表保持新到旧。现有 Host → sniffHost → 目的 IP 身份链、`queryEcho` 门和失败保留旧结果契约不回退。
- R8：修复不得记录、导出或在诊断中暴露具体 Host、IP、进程路径、链路节点或凭据；本机数据库只允许用脱敏聚合验证。
- R9：不通过手工改写用户数据库交付修复。任何归属恢复必须是可测试、幂等、可中断且失败可回滚 / 重试的产品路径，或是不写库的等价查询路径。

## Acceptance Criteria

- [ ] AC1：应用持续运行超过一个预设窗口后，自动刷新开启时「近 24 小时」查询的 `rangeEndUtc` 与当前时间相差不超过一个刷新周期；关闭自动刷新时界面明确显示已暂停，恢复或手动刷新后窗口立即推进。
- [ ] AC2：fixture 中 target=`家宽`、链路节点=`AI-家宽` 的既有 raw 会话按共享归属规则出现在家宽地址排名、趋势和份额中；完全无关节点不进入结果。
- [ ] AC3：完全相等的自定义 target 仍保持正确归属；多个候选 target 的 primary / tags 顺序稳定且有回归测试，不因恢复历史而产生双计数。
- [ ] AC4：给定 `primary_category_id` 全空但 `connection_chain` 完整的升级前 fixture，修复路径无需新采样即可返回非空 totals、series 和 rankings，并与同一规则下从 raw 会话计算的聚合量守恒。
- [ ] AC5：新采样的 `primary_category_id`、policy version、raw 查询和 hourly / daily 物化使用相同归属规则；跨 raw 保留边界的能力与结果差异被显式测试或诚实标为不支持。
- [ ] AC6：无命中、有命中、无覆盖、查询错误、暂停自动刷新、方向切换、Top N 切换和长驻窗口均有聚焦测试；旧请求不得覆盖新窗口结果。
- [ ] AC7：中文 / 英文、宽 / 窄窗口和深 / 浅主题下，实际窗口 / 最近更新、暂停提示、排名、趋势与空态可读；原生 WebView 未执行的组合保持 `UNVERIFIED`。
- [ ] AC8：前端 check、Rust workspace tests、相关 SQL / 存储回归、`just ci`、Trellis validate 和 `git diff --check` 通过；既有基线失败与本任务新增失败分开记录。

## Out of Scope

- 不把观测量宣传为运营商账单，不补齐控制器未提供的隧道内域名或采集缺口。
- 不修改 Clash Verge 全局扩展路由、用户私有脚本、凭据、告警规则或其它维度页的信息架构。
- 不新增云同步、遥测、长期原始流量无限保留或通用查询 DSL。
- 不在规划阶段手工修补当前 `monitor.sqlite3`；实施阶段只交付可重复的产品修复与验证。

## Product Decisions

- D1（用户于 2026-08-31 确认）：target=`家宽` 是受控语义选择器，匹配链路中名称包含「家宽」的节点；其它自定义 target 继续完全相等匹配。该共享规则同时用于实时筛选、未来历史核算和已有 raw 历史恢复。
- D2：已有历史恢复只承诺 raw 保留期内仍有 `connection_chain` 证据的记录；不根据 Host / IP 猜测 raw 期外分类，也不把不可恢复数据写成零。
- D3：沿用顶部刷新图标的“自动刷新 / 暂停”交互；从暂停恢复时立即推进窗口，不额外新增第二个手动刷新按钮。
