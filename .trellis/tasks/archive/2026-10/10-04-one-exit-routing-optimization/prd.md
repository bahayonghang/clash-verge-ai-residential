# 参考 one-exit 优化 AI 家宽路由规则

## Goal

在不扩大严格 AI-only 范围的前提下，改善现有规则的 DNS 一致性和住宅链路配置校验。初次请求只要求研究与规划；2026-10-04 用户随后批准按建议顺序实施两个子任务。

## Background（实施前基线）

- 参考：`ref/one-exit`，commit `151e1e4fb2c39334bcbce97c72d577b6802dabc2`；原文 https://x.com/wquguru/status/2106041666922783181 已读。
- 公共脚本版本 5.11.0。参考方案覆盖 Claude、Google 邮件/支付、Persona；本仓库要求严格 AI-only，不能直接移植全部清单。
- **F1 / P2**：规划时业务正则在 `clash-verge-ai-residential.js:1392-1399,1483-1488` 生效，DNS 在 `:1649-1679` 仅覆盖 exact/suffix。该例外已记录于当时的 `docs/dns-and-leak-model.md:32`；本次提出后续能力，不宣称已观测泄漏。
- **F2 / P2**：规划时可达上游的 empty-fallback 未进入 `clash-verge-ai-residential.js:1147-1224` 校验。虚构 Profile 的顶层/嵌套上游均能输出回指住宅节点的引用，详见研究。
- 完整对照、官方语法和初始复现保存在 `research/`；实施验证分别记录于两个子任务的 `research/validation.md`。

## Acceptance Criteria

- [x] **AC1 → R1**：DNS 子任务验收通过，业务规则集合不变，Vertex/Cursor 独立开关和旧输出清理有正反测试；无宽泛 Google/Cursor DNS 键。
- [x] **AC2 → R2**：回退子任务验收通过；虚构顶层/嵌套案例失败原因明确、输入不变、无自动 DIRECT 替换。
- [x] **AC3 → R3**：两项合并后未知规则与原 Profile 路由保持，extra 的 DNS 豁免保持，无产品范围外改动、凭据或依赖变化。
- [x] **AC4 → R4**：最终 `just ci` 与 `just docs-build` 通过，并保留脱敏实际内核验证记录；受阻项不得写成通过。Node 测试不替代实际 DNS/UDP 证明。
- [x] **AC5 → 规划交付**：已读取参考项目/介绍、形成证据报告，并创建父子任务的 PRD、设计、实施计划和上下文清单；规划阶段未改产品代码或本地配置。

## Out of Scope

不新增域名或业务路由，不恢复 clau.de、Anthropic /21、ASN，不引入 Google/Anthropic 宽后缀、关键词、Persona、邮件/支付或 Play/Wallet 进程路由。不更改现有认证开关默认值，不迁移 HTTP 代理，不自动选择中转地区，不添加 DIRECT 传输回退，不全局禁用 UDP/QUIC。

不修改 `*.local.toml` / `*.local.js`、ResiWatch、参考项目、依赖、版本号、发布流程或运行中的用户配置。不提交或推送，不读取私人流量数据库，不承诺流量节省或账号风控效果。

## Approval Boundary

用户已批准本规划内的顺序实施。新增范围、提交、归档、推送和生产配置操作仍需单独授权。DNS 能力若不被实际内核支持，应回到规划，不扩大后缀、不增加网络规则订阅、不降低 gate。
