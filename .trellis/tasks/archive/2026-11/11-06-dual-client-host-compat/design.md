# 共享脚本与宿主合同

## 结构

保持单一 CommonJS 可测试、宿主可粘贴脚本。首先检查现有实现与覆盖；不为两个客户端复制业务配置。兼容 fixture 只表达可证明的宿主输入，不复制整套宿主源码或 GPL 代码。

## 合同

1. 输入是配置对象；profileName 可缺省。缺省时遵循现有候选与最终规则上游解析，不凭空伪造订阅名来触发 PROFILE_UPSTREAM_OVERRIDES。
2. 同名保留对象碰撞要拒绝且输入不变。FlClash 顶层 rule-providers:null 已允许，不能扩大成接受所有错误类型。
3. module 不存在时宿主入口仍能执行；Node 测试只证明 JS 合同，Rust/QuickJS 和真实宿主需单独验证。
4. DNS 规则依据实际开关生成；GUI 后置覆盖由接入文档处理，不能在脚本内声称观测到宿主最终配置。
5. 业务规则顺序维持私网→AI 域名→现有 IP/可选捕获→原规则。未知自定义规则保留不意味着提到前面。
6. 进程查找用于观测，不等于全量进程路由；宿主关闭查找时需要对应设置说明，不自动启用进程捕获。

## 研究到实施的门槛

沿 Verge 固定 enhance 调用链、FlClash Dart 到 Rust 桥接及生成最终配置链核对。若现场版本与研究版本不同，记录实际 SHA/版本及差异。
只有针对宿主边界的可复现失败才能改根脚本；必须先记录具体函数和失败输入。若需要改变域名、DNS 算法、优先级、全局设置或默认开关，停止该修复并回父任务。

## 验证与回退

复用现有 regression 测试与默认 fixture；只添加能揭示真实兼容回归的测试。四平台组合的能力与实机检查交接到运行任务，避免将 Node VM 当成 QuickJS 的替代。若没有产品缺陷，交付可以只有文档和必要测试，不强行改脚本。
