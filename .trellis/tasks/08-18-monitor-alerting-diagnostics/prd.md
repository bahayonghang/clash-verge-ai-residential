# C4：家宽监控告警与诊断

## 目标与用户价值

在 C3 已验收的报告、汇总、保留和备份能力之上，交付可解释、可恢复且不会干扰采集账本的告警闭环。用户应能及时发现控制器或存储异常、持续流量峰值和周期用量越界，并在 Windows 通知未送达时仍从应用内告警中心取得完整记录和脱敏诊断。

本任务只把既有事实转化为告警和诊断，不改变 C1 的核算口径，不复制 C3 的周期聚合，也不把通知送达状态当成告警是否存在的依据。

## 前置条件与边界

- 本任务是 C4，严格依赖 C3 `08-18-monitor-reporting-data` 完成并通过独立验收。C3 未完成时不得启动 C4。
- C1 的 ingestion、`CommitBundle` 幂等写入和 coverage 语义继续作为事实源；C3 的 `ReportService`、小时 / 日汇总和查询能力继续作为周期用量的唯一统计源。
- C4 只追加告警规则、告警实例、告警事件和通知 outbox 所需的前向 migration，不修改已经发布或由 C1 / C3 拥有的 migration。
- 应用内告警中心是权威记录；Windows 系统通知是提交成功后的尽力送达副作用。
- 当前状态保持 `planning`。本次规划不授权运行 `task.py start`，也不授权编辑产品代码。

## 功能需求

### R1. 健康告警

- 支持控制器断线、TCP 鉴权失败、端点或协议不兼容、采集缺口、存储背压 / I/O 故障、迁移失败和备份失败。
- 健康告警使用既有 health、coverage 和维护结果，不用轮询日志反推状态。
- 同一根因反复抖动时必须去重并受冷却与恢复状态约束；恢复事件记录恢复时间和恢复前持续时长。

### R2. 60 秒滚动速率告警

- 规则可按主分类、域名或进程选择对象，并分别配置上行、下行或总速率阈值。
- 速率以单调时钟上的 60 秒滚动平均计算；只有连续 3 次评估都满足触发条件才进入活动状态。
- 恢复阈值支持滞回，避免在触发阈值附近反复活动 / 恢复。
- 首帧基线、核心重启、采集缺口和存储失败不得被解释为零速率，也不得用跨缺口平均值触发规则。

### R3. 周期用量告警

- 周期只允许滚动 1 小时、用户本地自然日和用户本地自然月。
- 周期用量必须复用 C3 的 `ReportService` / rollup、时区边界、coverage、策略版本与查询能力，不得建立第二套窗口聚合、第二套日 / 月计数器或独立扫描 raw 的私有口径。
- 本地自然日 / 月正确处理时区、夏令时和月份长度；证据保存 UTC 边界、本地时区与 data version。
- C3 返回能力不支持、coverage 不足、查询超时或数据版本不可用时，规则进入可见的不可评估状态，不把未知值当成零或未超限。

### R4. 规则与状态机

- 规则支持创建、编辑、启停、测试、冷却、恢复滞回和静默时段，并保存单调递增的规则版本。
- 活动、恢复、冷却、静默、不可评估和通知状态由单一状态机拥有；应用重启后从持久状态继续。
- 规则变更必须明确结束或重新基线化旧版本状态，不能把旧规则的连续命中计数继承给新阈值。
- 静默只抑制外部通知，不删除告警事件、不覆盖恢复记录，也不改变应用内告警中心的权威性。

### R5. 原子提交与幂等

- 同一采集批次产生的 facts、coverage、alert state / event 与 notification outbox 必须作为同一 `CommitBundle` 由单 writer 在一个 SQLite transaction 中提交。
- 事务成功后才允许发送 Windows 通知；事务失败时不得出现只有通知、没有应用内告警的状态。
- commit 结果不确定时沿用稳定 `bundle_id` 重试，不能重复累计事实、重复创建同一告警事件或重复入队同一通知意图。
- 通知失败只更新 outbox 的送达状态，不回滚已提交事实、coverage 或告警历史。

### R6. 可靠通知 outbox

- worker 在应用启动后立即扫描，并在运行期间按固定周期继续扫描。
- 扫描必须有适配索引、稳定顺序、批次上限和时间预算；不能无界读取全部历史。
- 认领使用原子 lease；记录 attempt、`next_attempt_at`、`lease_until` 和错误分类。崩溃留下的 stale lease 到期后可被下一实例回收。
- 可重试失败使用有上限的指数退避与抖动；永久失败进入明确 `failed` 状态并在告警中心可见，不得永久卡在不可见状态。
- 重复 worker tick、应用重启和发送结果不确定不能造成同一 outbox 项的并发重复认领。

### R7. Windows 通知与告警中心

- Windows 通知在真实 NSIS current-user 安装态、普通用户权限下验收；Focus Assist、通知被系统禁用或权限不可用时给出准确说明。
- 通知至少能打开或聚焦应用；测试通知与真实告警共用同一系统能力 seam，但不得伪造真实告警历史。
- 告警中心支持活动告警、历史、恢复时间、规则版本、通知状态和证据链接；规则输入有单位、范围、时区与静默预览。
- 告警证据至少包含规则版本、data version、窗口、过滤条件、coverage 和触发 / 恢复观测值，可打开同口径报告。

### R8. 脱敏诊断

- 诊断至少包含应用、schema、SQLite、mihomo 与 transport 版本，以及 last frame、coverage、reconnect、writer queue、DB / WAL、commit、checkpoint、backup、retention、告警与 outbox 健康。
- 诊断和日志按白名单投影并轮转；不得包含 TCP secret、Credential Manager 内容、原始完整域名 / IP、完整进程路径或未经脱敏的连接 payload。
- 诊断导出失败不得影响采集或告警提交；导出前显示包含项与脱敏说明。

### R9. 数据库与运行性能

- 告警评估和提交不得破坏 C1 ingestion SLO：10,000 活跃连接短峰时，frame → `CommitBundle` 计算 p95 仍小于 500 ms，frame → durable commit p95 仍小于 1.5 s，正常最大值小于 3 s，输入队列不持续超过 2 帧。
- 不得在每个采集 frame 为每条规则执行独立 SQL。速率窗口和规则匹配应共享有界内存投影；周期规则应批量消费 C3 报告 / rollup 能力。
- 告警与 outbox 写入使用缓存 prepared statements 和有界批量；索引数量与写放大必须通过基准证明。
- 对 health flapping、大量规则、通知持续失败、stale lease 回收和积压 outbox 进行压力测试；队列、扫描批次、内存和重试必须有界。

### R10. 数据保留

- 告警历史默认保留 180 天；清理复用 C3 的 retention 调度、批次、取消和 ingestion 优先级。
- 清理不得删除仍被活动告警、恢复证据或待处理 outbox 引用的数据；中断后可幂等续跑。

## 验收标准

- [ ] **C4-AC1 依赖与口径**：证据表明 C3 已通过独立验收；周期用量规则只调用 C3 报告 / rollup 和同源 coverage / 时区能力，schema 与运行时均不存在第二套小时、日或月聚合。
- [ ] **C4-AC2 健康闭环**：断线、TCP 鉴权失败、协议不兼容、采集缺口、存储、迁移和备份故障各自产生可区分的活动与恢复记录；同根因 flapping 不重复轰炸。
- [ ] **C4-AC3 速率规则**：确定性时钟测试证明 60 秒滚动平均连续 3 次满足才触发；第 1、2 次不触发，滞回阈值内不恢复，跨缺口不误报。
- [ ] **C4-AC4 周期规则**：滚动 1 小时、本地自然日和自然月在 DST、跨午夜、跨月、部分 coverage 和策略版本变化下与同参数 C3 报告完全一致；不可评估状态可见。
- [ ] **C4-AC5 原子性**：在 facts、coverage、alert、outbox 各写入点注入事务失败与 hard reset，重启后只出现全部提交或全部未提交；稳定 `bundle_id` 重试不产生重复事件或重复 outbox。
- [ ] **C4-AC6 outbox 恢复**：在 commit 后、首次发送前和 lease 持有期间终止进程；重启后的启动扫描和周期扫描能回收 pending / stale 项，按退避最终进入 `sent` 或明确 `failed`，不存在永久 stuck 项。
- [ ] **C4-AC7 通知与告警中心**：NSIS 安装态普通用户测试通知通过；通知不可用或发送失败时应用内记录、恢复时间、证据和送达状态仍完整，点击通知能打开或聚焦应用。
- [ ] **C4-AC8 脱敏诊断**：诊断包含规定的版本与健康字段；对 secret、凭据、完整敏感连接字段执行扫描结果为零，诊断失败不影响 ingestion。
- [ ] **C4-AC9 性能与有界性**：10,000 活跃短峰、health flapping、大量启用规则、通知持续失败和 outbox 积压组合压力下仍满足 C1 ingestion SLO；记录 p50 / p95 / p99 / max、CPU、RSS、队列、DB / WAL 与扫描批次，且没有逐 frame 逐规则独立 SQL。
- [ ] **C4-AC10 独立验证**：任务实施计划列出的自动测试、安装态通知 smoke、性能命令和全仓质量门全部通过；验收记录包含命令、环境、原始输出位置、门限判定、已知限制与回滚演练。

## 非目标

- 不计算费用、预算、费率或代理商账单，不把观测用量称为权威计费数据。
- 不增加短信、邮件、Webhook、云推送或远程告警服务。
- 不新增 Windows Service，也不承诺用户未登录期间送达通知。
- 不为周期用量另建 raw 扫描器、小时 / 日 / 月聚合或前端计数器。
- 不在本任务改写 C1 核算、C3 报告 / retention / backup 的业务语义。

## 规划结论

需求、范围、依赖、性能门和回滚边界已明确，无阻塞性开放问题。任务继续保持 `planning`，需在 C3 验收完成且用户审阅本规划后另行明确授权启动。
